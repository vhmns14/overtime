# Overtime security audit and bug hunt

Scope: the Worker (all `/api/ext/*` routes: ext, Hermes webhook, control, building, insights, notify, watch stream; the LLM/GitHub proxies, the page fetcher, previews), the Durable Objects, the Vite frontend and its service worker, the Hermes plugin (`integrations/hermes-overtime/__init__.py`, `overtime_control.py`, `install.sh`) and self-hosting (Dockerfile, compose, `scripts/selfhost.mjs`). Baseline: `4653946`. Everything was tested locally; nothing was pushed or deployed.

Method: code review with an attacker's view of each trust boundary, then an exploit test for each finding before fixing it. Real Hermes Agent 0.19.0 (`tools.approval`) drives the approval tests. The exploit tests live in `tests/security-audit.test.ts`, `tests/control.test.ts`, `integrations/hermes-overtime/tests/test_control.py`, `test_plugin.py`, `test_install.py`, `e2e/xss.spec.ts`, `e2e/audit.spec.ts`, `e2e/control.spec.ts` and `scripts/selfhost-smoke.mjs`.

Severity scale: **High** means an attacker gets a capability they should not have (approve, run, overwrite, read internal services). **Medium** covers integrity or confidentiality problems that need a precondition. **Low** covers defence in depth and hygiene.

## Findings

| ID | Severity | Finding | Status | Commit |
|---|---|---|---|---|
| H-1 | High | **A remote approval could be applied to a different command.** The plugin checked under Hermes' lock that the head of the gateway queue was "this command", released the lock, then called `resolve_gateway_approval`, which pops whatever is at the head *then* (FIFO). If the request was answered locally or timed out in between, and a different command was queued (or an older approval was ahead of it), the remote "approve" landed on that other command. The plugin now pins the exact `_ApprovalEntry` when `pre_approval_request` fires (Hermes queues the entry before it fires the hook, in the same thread). It then checks the entry, removes it and wakes it in one step under Hermes' lock, the same way `resolve_gateway_approval` does. Proven against real Hermes 0.19 with two concurrent approvals in one session. | fixed | `79d7917` |
| H-2 | High | **A pairing link was a permanent device credential.** The docs called it "one-time", but `/watch/…#…&c=ot_ctl_…` carried a live control token. It had no expiry and could be reused by anyone who later saw it (chat history, screenshot, browser sync). Pairing now issues an `ot_pair_…` code: hashed, single-use, valid 10 minutes, at most 5 outstanding. The new device swaps it for its own control token (`POST devices/claim`). A used or expired code returns 410. | fixed | `bf48ff2` |
| H-3 | High (self-host) | **SSRF through the page fetcher.** `/api/fetch` is unauthenticated and followed redirects (`redirect: "follow"`), so any public URL could bounce it to `127.0.0.1`, `169.254.169.254` or the self-host machine's LAN. `isPrivateHost` also missed IPv4-mapped IPv6 (`[::ffff:7f00:1]`), `::`, NAT64, CGNAT/Tailscale `100.64/10`, trailing-dot `localhost.` and wildcard-DNS names (`127.0.0.1.nip.io`). Every redirect hop is now followed by hand and re-checked, and the host check covers those forms. | fixed | `bb60c98` |
| H-4 | High | **Preview IDOR.** `PUT /api/runs/<id>` replaced any preview, and preview ids are public (`/p/<id>/`). Anyone with a preview link could replace it with a phishing page on the Overtime origin. The first upload now sets a write key (`x-ot-preview-key`, 192-bit, per tab), and replacing the preview requires it. | fixed | `bb60c98` |
| M-1 | Medium | **Two devices answering at once both got "200".** `approval.decide` checked `pending`, awaited the HMAC, then ran an `UPDATE … WHERE status='pending'` without checking it. The losing device was told "Denied" while "Approve" had been applied, and the audit log held two answers. The first answer now wins (`RETURNING`), and the other device gets 409 with the real status. | fixed | `bf48ff2` |
| M-2 | Medium | **Audit chain forks and lost entries.** Concurrent `audit()` calls (for example several approvals expiring in one request, or interleaved requests) read the same last `seq`. The second INSERT then failed: an unhandled rejection, a 500 after the state change, a missing entry. Appends are now serialized through a promise chain. | fixed | `bf48ff2` |
| M-3 | Medium | **Approving what you cannot see.** The approval card showed the command clipped to 2000 characters, but the signature bound the full command, so a long command could hide its dangerous tail. An unterminated `-----BEGIN … PRIVATE KEY-----` marker also redacted everything after it. A command longer than 4000 characters is now flagged `truncated`: the server refuses `once`/`session` (409) and the UI offers Deny only. Commands with hidden parts are flagged `redacted` and the UI says so. The PEM pattern now only eats base64 lines. | fixed | `bf48ff2`, `91e2203`, `79d7917` |
| M-4 | Medium | **Task replay and double execution.** The plugin kept no record of command ids and set no age limit, so the same signed command delivered twice ran twice. That covers a server bug, a retry, or a replay over plain http. The plugin now remembers the last 1000 handled ids (a duplicate is ignored and never acked) and refuses tasks older than `OVERTIME_TASK_MAX_AGE` (default 3600 s). | fixed | `79d7917` |
| M-5 | Medium | **Slash-command allowlist bypass.** The check was `prompt.lstrip().startswith("/")`. It was bypassed by a fullwidth `／`, a division slash `∕`, or a zero-width space, BOM or bidi mark before `/`. The check now applies NFKC folding and skips whitespace and format characters first. On the server side, prompts with bidi controls are refused, because the confirmation screen would show something other than what is sent. | fixed | `79d7917`, `bf48ff2` |
| M-6 | Medium | **Tokens replayed on redirects.** The plugin's `viewer_link` and the control HTTP client used `urlopen`, which repeats the `Authorization` header (the ingest token, or `API_SERVER_KEY` toward the Hermes API) to any host a `Location` names. The LLM proxy followed redirects with the user's key. Redirects are now never followed in the plugin, and the LLM proxy uses `redirect: "manual"` and returns 502 on a 3xx. | fixed | `79d7917`, `bb60c98` |
| M-7 | Medium | **Redaction gaps** (both the plugin and the Worker): `API_SERVER_KEY=` and other `*_KEY`/`*_TOKEN` variables, Telegram bot tokens, Stripe `sk_live_`/`rk_live_`, `npm_`, `pypi-`, Google `ya29.`, DigitalOcean, GitLab (Python), Slack and Discord webhook URLs, `--password`/`--token` flags, and `token <value>` (Python). Both sides now share one pattern list. | fixed | `79d7917`, `91e2203` |
| M-8 | Medium | **Metadata privacy sent URL paths.** For example `api.telegram.org/bot<token>/sendMessage`. The README promised "URL hosts". Metadata now keeps the host only (args and full keep host and path). | fixed | `79d7917`, `91e2203` |
| M-9 | Medium | **Self-host exposure.** (a) Secrets were passed to workerd as `--var KEY:VALUE` argv, which every user and container on the host can read with `ps`. They now go through a private 0600 env file (`--env-file`). (b) Compose published `8787` on all interfaces, and Docker-published ports bypass ufw. It now defaults to `127.0.0.1` (`OVERTIME_BIND` to change it). (c) The inspector is now pinned to 127.0.0.1. | fixed | `b56b816` |
| M-10 | Medium | **Floor race in buildings.** If a viewer switched floors while one office was still loading, that office's events were ingested into the next floor, and its live stream was opened as well. Each connect now has a generation token, and stale answers are dropped. An e2e test delays floor A by 1.5 s and asserts that nothing of A appears on B and that at most one live WebSocket stays open. | fixed | `34efadc` |
| L-1 | Low | Write-capable tokens were accepted in `?v=` (the ingest token for `share` and ingest POSTs, the building admin token), so they could leak into logs, proxies and Referer headers. Only `ot_view_`/`ot_bview_` tokens are accepted there now. The WebSocket stream never takes the ingest token. | fixed | `91e2203` |
| L-2 | Low | Webhook deliveries without `delivery_id` could be replayed inside the 5-minute timestamp window. They are now deduplicated by signature. | fixed | `91e2203` |
| L-3 | Low | Unbounded growth. The session and subagent index outlived pruned events, and `ctl_sent`, `ctl_audit`, `ctl_approvals`, `ctl_commands` and revoked devices had no caps. They are now pruned with events, with caps of 5000/2000/500/500/50. Pending approvals and open tasks are never pruned. | fixed | `91e2203`, `bf48ff2` |
| L-4 | Low | Control and building routes read the whole body before checking its size. `content-length` is now checked first. | fixed | `bf48ff2`, `91e2203` |
| L-5 | Low | The Telegram HTML `href` did not escape `"`. | fixed | `91e2203` |
| L-6 | Low | The service worker opened any http(s) URL from a push payload, so a forged push would have been an open redirect. It now opens same-origin URLs only, otherwise the scope. | fixed | `91e2203` |
| L-7 | Low | Added `Cross-Origin-Opener-Policy: same-origin` and legacy `X-Frame-Options: DENY` next to the existing CSP `frame-ancestors 'none'`. | fixed | `91e2203` |
| L-8 | Low | Markdown export breakout: a tool name, model or path containing backticks, pipes or newlines could end a code span, split a table row or start a heading. | fixed | `0fe2555` |
| L-9 | Low | `install.sh`: it wrote a temp copy of `~/.hermes/.env` (including `API_SERVER_KEY`) and the plugin files under umask 022, put the token on curl's argv, and verified nothing. Now it uses `umask 077`, sends the header from stdin (`-H @-`), accepts `OVERTIME_TOKEN` from the environment, verifies `SHA256SUMS` (emitted at build), and warns on plain http to a public host. | fixed | `b56b816` |
| L-10 | Low | `.env` (which SELF_HOST.md tells you to create, with secrets) was neither git-ignored nor docker-ignored. | fixed | `b56b816` |
| L-11 | Low | A throwing notification inside `alarm()` would exhaust the runtime's alarm retries and drop the office's TTL and stuck alarm. | fixed | `34efadc` |
| L-12 | Low (bug) | Server-side budgets synced from Insights kept `quiet.tz = UTC`, so a user in Asia/Jakarta had their "day" roll over at 07:00. The browser's time zone is now sent along. | fixed | `34efadc` |
| L-13 | Low | Defence in depth: a decision that arrives after the plugin's own wait is never applied. Plain-http `OVERTIME_URL` to a public host logs a warning. TLS verification is asserted never to be turned off. | fixed | `79d7917`, `628af86` |

## Accepted risks (by design, documented)

| ID | Severity | Risk | Why accepted / mitigation |
|---|---|---|---|
| A-1 | Medium | The HMAC key for decisions and tasks is SHA-256(ingest token), which the office stores. A malicious or compromised Overtime server, or anyone who can read the Durable Object's storage, can forge a decision for the *current* request or queue any task. | The signature authenticates the server to the plugin, not a device. Limits: both sides must opt in; a decision is bound to the random request id and command hash and the pinned entry; there is no remote `always`; tasks go through the allowlist, the slash refusal, the length and age limits, and are never run twice; tasks start new runs under Hermes' own approval rules. Roadmap: device-held keys that the plugin pins. |
| A-2 | Low | Without `OVERTIME_SECRET_KEY`, the Telegram token's AES-GCM key lives next to the ciphertext in the same DO, so encryption at rest only stops casual reads. | Set `OVERTIME_SECRET_KEY` (documented). IVs are random 96-bit per seal, keys are HKDF-derived per office (context `telegram:<office>`), and there is no IV reuse. |
| A-3 | Low | The VAPID private key, the audit signing key, the view token and the webhook secret are stored in clear in the office DO. | The office must use them (sign, serve, verify). VAPID keys can come from Worker secrets instead. |
| A-4 | Low | Ingest and view tokens and the webhook secret cannot be rotated; the only way is a new office. | Roadmap. Devices are revocable at once. |
| A-5 | Low | The owner tab keeps the ingest token, and paired devices keep their control token, in localStorage. | This is the owner's own device. The CSP allows no inline script, and every view escapes event content (XSS sweep e2e). |
| A-6 | Low | The CSP has `'unsafe-eval'`, used by the Reviewer's `new Function` syntax check, and `connect-src https:` for bring-your-own LLM endpoints. | Documented in the README. |
| A-7 | Low | The view token is in the WebSocket URL, because browsers cannot set headers on a WebSocket. | It is read-only; write tokens are refused there (L-1). |
| A-8 | Low | The ingest token can pair the first device while none is paired. | This is the bootstrap path. The Hermes machine is the trust root anyway. |
| A-9 | Low | Office and building creation limits are per isolate, and control routes are not rate limited. | Tokens are 192-bit, pairing codes are single-use with a 10-minute life, and per-office token buckets guard ingest. |
| A-10 | Low | An office can hold up to 50,000 events of at most 16 KB each. | Only the owner (ingest token) writes, at 200 events/s, and offices are deleted after 30 days idle. |
| A-11 | Low (self-host) | DNS names that resolve to private addresses (other than the wildcard services above) still pass the SSRF check, because Workers cannot resolve DNS. | On Cloudflare the edge cannot reach private ranges. Self-hosters should run with an egress firewall (documented). |
| A-12 | Info | `npm audit`: `vitest` 3.2.7 → `@vitest/mocker` (moderate) and `tinypool` 1.1.1 (critical, prototype-pollution gadget). Dev-only; the fix needs a major vitest upgrade. | These run only in tests. They ship inside the Docker image's `node_modules` (wrangler is a devDependency) but are never executed there. |
| A-13 | Info | The Docker base image is pinned by tag (`node:22-bookworm-slim`), not by digest. | The image runs as the non-root `node` user and bakes in no secrets (`.dockerignore` now covers `.env`/`.dev.vars`/`*.pem`). |
| A-14 | Info | `curl … install.sh \| sh` trusts your own server. `SHA256SUMS` comes from the same origin, so it catches truncated or mixed downloads but proves nothing about who published them. | The files are also served for manual download and review. |
| A-15 | Info | Plugin threads: one per pending gateway approval (at most Hermes' approval timeout, capped at 900 s) and one tracker per started task (polls every 5 s, at most 6 h). | Bounded by Hermes' own queue and Overtime's 5 open tasks. Every hook is wrapped and never raises or blocks. |

## Verified, no change needed

- Token separation: the view token never writes, shares or controls; the ingest token only writes, registers and reads decisions and claims tasks; only `ot_ctl_` decides, queues and pairs. IDOR across offices and buildings: tokens of one office or building never open another, and a building cannot adopt an office without that office's ingest token (exploit tests in `tests/security-audit.test.ts`).
- Constant-time comparisons: `safeEqual` on fixed-length hex digests in the Worker, `hmac.compare_digest` in the plugin.
- Tokens are 24 random bytes (192 bits). Ingest, control, building and pairing tokens are stored as SHA-256 hashes. Device revocation takes effect on the next request.
- Webhooks: HMAC-SHA256 over the raw body (GitHub style), a signed timestamp within ±5 minutes, at most 256 KB and 200 items, per-office request and event buckets.
- Web Push: aes128gcm per RFC 8291 (round-trip test), ES256 VAPID JWT, endpoints limited to browser push services. Quiet hours, a 10-minute dedupe per key and 12 messages per hour per channel are enforced server-side.
- The frontend escapes every event-derived string. The XSS sweep e2e puts break-out payloads in every agent-controlled field at `full` privacy and opens the office, panel log, library hover and panel, every Insights tab, timeline search, building and floor names, the approval card, task confirm and list, and device names. No element, handler or `javascript:` link appears, and no CSP violation is logged.
- Secret scan of the whole history (22 commits) with gitleaks-style patterns: the only matches are obvious test fixtures (`tests/*`, `e2e/*`, demo tokens).
- `pip-audit`: the plugin has no third-party Python dependencies (stdlib only).
